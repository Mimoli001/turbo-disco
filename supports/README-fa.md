# ویندوز ماندگار روی GitHub Actions

**دسکتاپ Windows Server در مرورگر، همراه با checkpoint رمزنگاری‌شده، بازیابی خودکار و اجرای مجدد پیش از سقف شش‌ساعتهٔ رانر.**

[English](../README.md) · [فارسی](README-fa.md)

![وضعیت ورک‌فلوی ویندوز](https://github.com/Mimoli001/turbo-disco/actions/workflows/windows.yml/badge.svg)

</div>

## امکانات

- Windows Server 2025 روی رانر ثابت `windows-2025-vs2026`.
- دسکتاپ مرورگری با noVNC و Remote Desktop اصلی از طریق `cloudflared`.
- کپی یکسان از کل پروفایل کاربر `runneradmin` با VSS؛ بنابراین فایل‌های باز و قفل‌شده هم از یک لحظهٔ ثابت خوانده می‌شوند.
- تنظیمات رجیستری کاربر، فهرست برنامه‌های نصب‌شده و package manifestهای Winget، Chocolatey، pip کاربر و npm سراسری.
- checkpoint با رمزنگاری AES-256 در Release خصوصیِ `windows-state`. هر بسته حداکثر **۱۹۰۰ مگابایت** است و از محدودیت ۲ گیگابایتی هر فایل GitHub عبور نمی‌کند.
- کنترل خرابی با SHA-256 و احراز اصالت با HMAC-SHA256، نگهداری سه checkpoint کامل و بازگشت به نسخهٔ قدیمی‌تر اگر جدیدترین نسخه ناقص یا خراب باشد.
- ذخیرهٔ خودکار هر ۱۵ دقیقه در صورت تغییر، checkpoint نهایی بعد از ۳۲۰ دقیقه و شروع اجرای تازه با همان وضعیت.
- بازیابی OpenBot با پروفایل، ثبت در logon کاربر و اجرای آن داخل مرحلهٔ طولانی نشست.

> **محدودهٔ دقیق:** این روش دادهٔ کاربر و وضعیت قابل انتقال برنامه‌ها را حفظ می‌کند؛ تصویر bare-metal ویندوز یا محتوای RAM نیست. سیستم‌عامل پایه را همیشه GitHub عرضه می‌کند. بعضی لاگین‌های وابسته به DPAPI یا سرویس مقصد ممکن است روی ماشین تازه دوباره تأیید بخواهند. کش‌های قابل ساخت مجدد و App Execution Aliasهای وابسته به ماشین ذخیره نمی‌شوند.

## شروع

1. Secretهای جدول پایین را بسازید.
2. مسیر **Actions → Windows Virtual Machine → Run workflow** را باز کنید.
3. برای ادامهٔ خودکار `chain=true` بگذارید؛ برای یک نشست تنها آن را خاموش کنید.
4. بعد از بررسی اتصال، آدرس `https://web.<zone-شما>/vnc.html` را باز کنید.
5. رمز VNC نمایش‌داده‌شده در لاگ را وارد کنید. روش RDP اصلی هم در همان‌جا نوشته می‌شود.

اجرای اول یک وضعیت تازه می‌سازد. اجراهای بعدی پیش از روشن‌کردن دسکتاپ، جدیدترین checkpoint سالم را بازیابی می‌کنند.

## Secretهای لازم

| Secret | کاربرد |
| --- | --- |
| `CF_API_TOKEN` | توکن Cloudflare با **Cloudflare Tunnel:Edit**، **DNS:Edit** و **Zone:Read** |
| `CF_DOMAIN` | دامنه یا ساب‌دومین برای پیدا کردن Zone در Cloudflare |
| `PASSWORD` | رمز حساب ویندوز؛ ۸ کاراکتر اول آن رمز VNC هم هست |
| `STATE_PASSPHRASE` | عبارت تصادفی بلند و مستقل برای رمزنگاری همهٔ checkpointها |
| `GH_PAT` | توکن GitHub با دسترسی **Contents: Read and write** و **Actions: Read and write** برای آپلود Release و اجرای ورک‌فلوی بعدی |

Secretهای اختیاری: `CF_ACCOUNT_ID`، `CF_RDP_HOST` و `CF_WEB_HOST`. نام‌های پیش‌فرض `rdp.<zone>` و `web.<zone>` هستند.

مخزن را **خصوصی** نگه دارید. checkpointها عمداً شامل پروفایل مرورگر، دادهٔ برنامه‌ها و احتمالاً توکن‌های لاگین قابل استفاده‌اند. اگر `STATE_PASSPHRASE` گم یا تغییر کند، checkpointهای قبلی قابل رمزگشایی نیستند؛ یک نسخهٔ بازیابی از آن را در password manager نگه دارید.

## checkpoint و اجرای خودکار بعدی

| تنظیم | پیش‌فرض | مقدار مجاز |
| --- | --- | --- |
| `session_minutes` | `۳۲۰` دقیقه | ۳۰ تا ۳۳۰ |
| `save_interval_minutes` | `۱۵` دقیقه | ۵ تا ۱۲۰ |
| `chain` | `true` | true / false |

این زمان‌بندی برای آپلود نهایی چندگیگابایتی پیش از سقف سخت شش‌ساعته فرصت می‌گذارد. اجرای بعدی با گروه همزمانی `windows-persistent` منتظر می‌ماند تا اجرای قبلی کاملاً تمام شود.

برای درخواست ذخیره از داخل ویندوز:

```powershell
New-Item -ItemType File -Path "$HOME\.save-now" -Force
```

حلقهٔ نشست این فایل را حذف و ذخیره را شروع می‌کند. اگر پروفایل تغییری نکرده باشد، fingerprint یکسان است و آپلود انجام نمی‌شود. خطای ذخیره، checkpoint کامل قبلی را خراب نمی‌کند و در نوبت بعد دوباره تلاش می‌شود. فقط سه checkpoint کامل آخر نگه داشته می‌شوند.

برای دیدن وضعیت یا آزمون غیرمخرب آخرین نسخه:

```powershell
.github/windows/state.ps1 status
.github/windows/state.ps1 verify
```

دستور `verify` جدیدترین checkpoint را دانلود، hash و رمزگشایی و در فضای موقت باز می‌کند، اما **آن را روی پروفایل فعال اعمال نمی‌کند**.

### چه چیزهایی بازیابی می‌شود

- Desktop، Documents، Downloads، پروژه‌ها، پروفایل مرورگرها، دادهٔ برنامه‌ها و بقیهٔ پروفایل کاربر، به‌جز کش‌های قابل ساخت مجدد.
- تنظیمات کاربر در `HKCU`.
- بسته‌های مفقود Winget بدون ارتقای بسته‌های موجود، و نیز بسته‌های Chocolatey، pip کاربر و npm سراسری اگر package manager موجود باشد.
- نصب و ثبت اجرای OpenBot برای logon کاربر.

بازیابی از `/MIR` استفاده نمی‌کند و فایل‌های رانر تازه را حذف نمی‌کند. پایگاه‌های دادهٔ داخلی ویندوز که همچنان memory-map شده‌اند، مانند WebCache یا Notifications، با هشدار رد می‌شوند تا کل بازیابی متوقف نشود. خود ویندوز، فایل‌های سیستمی ازپیش‌نصب‌شده، kernel، processهای در حال اجرا و RAM جایگزین نمی‌شوند. اگر نسخهٔ قدیمی برنامه‌ای دیگر در دسترس نباشد، نصب آن ممکن است کامل نشود.

تقسیم فایل فقط محدودیت **۲ گیگابایت هر asset** را حل می‌کند؛ زمان آپلود، پهنای‌باند و محدودیت‌های سرویس GitHub همچنان وجود دارند. فاصلهٔ ۱۵ دقیقه برای پروفایل چندگیگابایتی ویندوز انتخاب شده است.

## اتصال

### مرورگر؛ پیشنهاد اصلی

```text
https://web.<zone-شما>/vnc.html
```

TightVNC فقط از مسیر Cloudflare تنظیم‌شده منتشر می‌شود. Loopback عمداً فعال است، چون noVNC و تونل هر دو به سرویس محلی وصل می‌شوند.

### Remote Desktop اصلی

روی رایانهٔ خود `cloudflared` را نصب و دستور چاپ‌شده در لاگ را اجرا کنید:

```bash
cloudflared access tcp --hostname rdp.<zone-شما> --url localhost:3389
```

سپس `mstsc` را به `localhost:3389` وصل کنید. اتصال خام RDP مستقیم به hostname کلادفلر ممکن نیست.

## رفع اشکال

| نشانه | راه‌حل |
| --- | --- |
| خطای checksum یا decrypt هنگام بازیابی | اسکریپت خودکار checkpoint کامل قدیمی‌تر را امتحان می‌کند. مطمئن شوید `STATE_PASSPHRASE` تغییر نکرده است. |
| ذخیره رد می‌شود | مرحلهٔ restore کامل نشده است. این محافظ جلو رانر تازه را از بازنویسی وضعیت سالم می‌گیرد. |
| autosave خطا می‌دهد | checkpoint کامل قبلی سالم می‌ماند و نوبت بعد دوباره تلاش می‌شود. لاگ و دسترسی‌های `GH_PAT` را بررسی کنید. |
| اجرای جدید شروع نمی‌شود | ذخیرهٔ نهایی باید موفق و `chain` فعال باشد. دسترسی `GH_PAT` به dispatch را بررسی کنید. |
| دسکتاپ مرورگری در دسترس نیست | نتیجهٔ handshake سرویس VNC و بررسی HTTP عمومی noVNC را در مرحلهٔ طولانی نشست ببینید. |
| لاگین دوباره لازم می‌شود | بعضی credentialها به ماشین قبلی گره خورده‌اند یا منقضی شده‌اند؛ برای DPAPI و نشست‌های باطل‌شدهٔ سرویس طبیعی است. |
| فضای دیسک کم است | فضای موقت `D:\windows-state-work` است. فقط سه checkpoint آپلودی نگه داشته می‌شود؛ پوشه‌های ناقص محلی را فقط بعد از توقف process ذخیره پاک کنید. |

## ساختار پروژه

```text
.github/workflows/windows.yml   سرویس‌های ویندوز، restore، autosave، ذخیرهٔ نهایی و chaining
.github/windows/state.ps1       VSS، رمزنگاری، بسته‌بندی، اعتبارسنجی، بازیابی و retention
cf_tunnel.py                    مسیرهای Cloudflare برای RDP و noVNC
supports/README-fa.md           راهنمای فارسی
```

## نکات امنیتی

- `STATE_PASSPHRASE`، `GH_PAT`، اطلاعات Cloudflare و فایل محلی عبارت رمز را هرگز commit نکنید.
- checkpoint پیش از آپلود رمزنگاری می‌شود، اما نام و اندازهٔ assetها برای دارندگان دسترسی به مخزن دیده می‌شود.
- اطلاعات اتصال و لاگ اجرا را در زمان روشن‌بودن ماشین حساس بدانید.
- ورک‌فلوی ناشناس را اجرا نکنید؛ به همان Secretها و پروفایل رمزگشایی‌شده دسترسی خواهد داشت.
- Cloudflare Access عمداً لازم نیست. رمز ویندوز و رمز VNC محافظ endpointهای دسکتاپ هستند.
